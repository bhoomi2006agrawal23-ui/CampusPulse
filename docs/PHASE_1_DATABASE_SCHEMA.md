# CampusPulse — Database Schema & Data Models Specification
**Document Version:** 1.0.0  
**Phase:** 1 (Architecture & Database Blueprint)  
**Status:** Complete & Locked  
**Database Engine:** MongoDB Atlas (Mongoose ODM)

---

## 1. Schema Overview & Design Philosophy

The CampusPulse data layer is structured to enforce strong referential integrity, schema-level validation, and concurrency safety.
- **14 Core Collections/Models:** Exactly 14 foundational models are defined for Phase 2 implementation.
- **15th Planned Collection:** `audit_logs` = 15th planned collection, **STRICTLY DEFERRED TO PHASE 6**. Do NOT create audit_logs in Phase 1 or Phase 2.
- **Denormalization vs. References:** Normalized ObjectId references are utilized for core relational boundaries (Events, Users, Venues, Categories), while snapshot metadata (e.g., student names or certificate verification tokens) is embedded only where historical immutability is required.
- **Attendance Storage:** Attendance/participation tracking remains inside the `registrations` model (`attendanceStatus: 'Attended' | 'Absent' | 'Excused'`, `checkedInAt`). DO NOT create a separate attendance collection.
- **Individual Student Registration:** The system implements individual student registration first. Team registration is deferred to future phases.
- **Server-Side Validation:** All registration window checks (`currentTime >= registrationStart AND currentTime <= registrationEnd`) and capacity enforcement are executed server-side.
- **Venue Conflict Acceleration:** The compound index `{ primaryVenueId: 1, startDateTime: 1, endDateTime: 1 }` (or `{ venueId: 1, startDateTime: 1, endDateTime: 1 }`) is only for query acceleration and does NOT itself prevent time-range overlap. Concurrent venue reservation protection must use MongoDB transaction/concurrency-safe logic during Phase 3.

## 3. The 14 Core Collections Detailed Specification

### 3.1. `users` Collection
Stores student, organizer, judge, volunteer, and administrator identity profiles.

| Field | Type | Required | Constraints / Default | Description |
|---|---|---|---|---|
| `_id` | ObjectId | Yes | Auto-generated | Primary key |
| `name` | String | Yes | Trim, min 2, max 100 | Full name of the user |
| `email` | String | Yes | Unique, Lowercase, valid email | Institutional / personal email address |
| `passwordHash` | String | Yes | bcrypt hash | Securely hashed password (min 12 salt rounds) |
| `role` | String | Yes | Enum: `['Student', 'Organizer', 'Judge', 'Volunteer', 'Admin']`, default: `'Student'` | User privilege level |
| `phoneNumber` | String | No | Optional, regex match for international / domestic format | Contact phone number |
| `bio` | String | No | Max length 300 characters | Short bio or department summary |
| `profileInfo` | Object | No | `{ department?: String, studentId?: String, year?: Number, avatarUrl?: String }` | Extensible profile metadata |
| `status` | String | Yes | Enum: `['Active', 'Suspended', 'Pending']`, default: `'Active'` | Account access status |
| `createdAt` | Date | Yes | Auto timestamp | Record creation date |
| `updatedAt` | Date | Yes | Auto timestamp | Record modification date |

**Indexes:**
- `{ email: 1 }` (Unique)
- `{ role: 1 }`
- `{ status: 1 }`

### 3.2. `sessions` Collection
Manages cryptographically secure refresh token sessions for JWT token rotation.

| Field | Type | Required | Constraints / Default | Description |
|---|---|---|---|---|
| `_id` | ObjectId | Yes | Auto-generated | Primary key |
| `userId` | ObjectId | Yes | Ref: `'User'` | Associated user reference |
| `tokenHash` | String | Yes | SHA-256 hash | One-way hash of the issued refresh token |
| `userAgent` | String | No | Max 255 chars | Browser client user-agent string |
| `ipAddress` | String | No | IPv4 / IPv6 string | Client IP address for fraud detection |
| `isRevoked` | Boolean | Yes | Default: `false` | True if explicitly invalidated or rotated |
| `expiresAt` | Date | Yes | Default: `now + 7 days` | Session expiration boundary |
| `createdAt` | Date | Yes | Auto timestamp | Session initialization time |
| `updatedAt` | Date | Yes | Auto timestamp | Last token rotation timestamp |

**Indexes:**
- `{ tokenHash: 1 }` (Unique)
- `{ userId: 1 }`
- `{ expiresAt: 1 }` (TTL index for automatic purging of expired sessions)

### 3.5. `events` Collection
Primary event entity governing lifecycle, ticketing/registration limits, and venue reservations.

| Field | Type | Required | Constraints / Default | Description |
|---|---|---|---|---|
| `_id` | ObjectId | Yes | Auto-generated | Primary key |
| `title` | String | Yes | Trim, min 3, max 150 | Event title |
| `eventCode` | String | Yes | Unique, Uppercase, alphanumeric | Unique code (e.g., `"CP-2026-HACK"`) |
| `slug` | String | Yes | Unique, Lowercase | URL slug (e.g., `"annual-hackathon-2026"`) |
| `description` | String | Yes | Max 5000 chars | Comprehensive event markdown / details |
| `categoryId` | ObjectId | Yes | Ref: `'Category'` | Event category reference |
| `organizerId` | ObjectId | Yes | Ref: `'User'` | Responsible organizer user |
| `primaryVenueId`| ObjectId | Yes | Ref: `'Venue'` | **Mandatory** primary campus venue |
| `startDateTime` | Date | Yes | ISO Date | Event commencement date and time |
| `endDateTime` | Date | Yes | Must be > `startDateTime` | Event conclusion date and time |
| `registrationStart` | Date | Yes | Must be < `registrationEnd` | Opening of student registration window |
| `registrationEnd` | Date | Yes | Must be <= `startDateTime` | Closing of registration window |
| `capacity` | Number | Yes | Min 1, integer | Maximum permitted registrants |
| `registeredCount` | Number | Yes | Default: 0, <= `capacity` | Current count of confirmed registrations |
| `status` | String | Yes | Enum (10 states + Cancelled), Default: `'Draft'` | Current lifecycle phase |
| `bannerUrl` | String | No | Valid image URL | Poster/banner image hosted via ImgBB |
| `eligibility` | String | No | Max 500 chars | Department/year restrictions |
| `instructions` | String | No | Max 2000 chars | Entry instructions and participant guidelines |
| `createdAt` | Date | Yes | Auto timestamp | Timestamp |
| `updatedAt` | Date | Yes | Auto timestamp | Timestamp |

**Lifecycle Enum Values:**
`['Draft', 'Published', 'RegistrationOpen', 'RegistrationClosed', 'EventUpcoming', 'EventOngoing', 'EventCompleted', 'ResultsPublished', 'CertificatesGenerated', 'Archived', 'Cancelled']`

**Indexes:**
- `{ eventCode: 1 }` (Unique)
- `{ slug: 1 }` (Unique)
- `{ categoryId: 1 }`
- `{ organizerId: 1 }`
- `{ status: 1 }`
- `{ startDateTime: 1, endDateTime: 1 }`
- `{ primaryVenueId: 1, startDateTime: 1, endDateTime: 1 }` (Venue conflict query acceleration)

## 4. Explicitly Deferred Collection: `audit_logs`

- **Roadmap Position:** Collection #15.
- **Implementation Status:** **DEFERRED TO PHASE 6**.
- **Reasoning:** In Phase 1 and Phase 2, developer velocity and schema cleanliness are prioritized on free-tier database limits. Audit log retention policies, ring buffers, and privileged action change captures will be introduced during Phase 6 (Testing, QA & Security Hardening) without mutating core operational entities.
